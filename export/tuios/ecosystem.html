Chapter 10 tuios manual

TUIOS: Ecosystem and Plugin Directory

A source-checked directory of everything found on the public internet that plugs into, extends, integrates with or packages tuios, with links, as of 7 October 2026.

tuiosecosystempluginslinks

tuios has no plugin registry and no plugin host of its own. What it has instead are several open edges: dock components are shell commands, themes are JSON files, coding-agent harnesses report through hooks tuios writes for them, the daemon speaks a JSON protocol that other programs can drive, it emulates the herdr socket so herdr tools work unchanged, and it ships a tmux shim. The ecosystem therefore lives in other people’s repositories, dotfiles and package feeds rather than in one place. This chapter is that place, as of 7 October 2026 against tuios v0.8.5.

Every entry was checked by fetching the page, by a GitHub, npm or package-registry API call, or by GitHub code search; the few that were only seen in search results are marked with a dagger (†). “n/l” means no licence was visible. “Updated” is the repository’s last push unless noted. Nothing here is endorsed by the tuios project unless the entry says it is first-party or linked from the project’s own docs. Treat third-party scripts as untrusted until you have read them.

How this list was built: every .md, .nix, .toml and .sh file in the tuios repository at tag v0.8.5 and the hosted docs’ llms-full.txt were scanned for outbound links; GitHub repository, code, issue and pull-request searches were run for tuios and for strings only a tuios integration would contain ([dock.custom, tuios set-agent-state, tuios-agent-state, TUIOS_PANE_ID, tuios.sock.herdr); the AUR, Homebrew, Repology, GHCR, Chocolatey, conda and npm registries were queried; and web search was run in both standard and extended modes. The last section lists what came up empty so you know the search was done.

Dock components

A dock component is a [dock.custom.<name>] table in config.toml with a command, a refresh policy (once, push, an interval such as "5s", or event:<name>), an optional on-click, and a max-width; it is placed in a region with custom/<name>. The complete contract and a worked recipe are in How To: add a dock component.

Themes

tuios bundles 342 themes from the bubbletint palette library. A custom theme is a JSON file in ~/.config/tuios/themes/ with id, display_name, fg, bg, cursor, the eight ANSI colours and their bright_* variants, and tuios import-theme converts kitty, Ghostty, Alacritty and WezTerm schemes. The schema is in Configuration; writing one is in How To.

Coding-agent harness integrations

tuios integration install [harness...] writes managed hooks or plugins into each harness’s own configuration. Twelve harnesses report full state (claude-code, codex, copilot, cursor-agent, gemini-cli, opencode, kilo, amp, kimi, pi, omp, qwen); seven report the session only (antigravity, crush, devin, droid, grok, hermes, qoder). The plugin sources live in the tuios tree under internal/integration/assets/ and integrations/claude-code/. The mechanics are in Agents; adding a harness is in How To.

MCP

tuios mcp is a stdio MCP server whose tools mirror daemon verbs. tuios integration install <harness> --mcp registers it read-only (or --mcp-write with writes) for Claude Code, Codex, Gemini CLI and opencode; other clients register it by hand, for example claude mcp add tuios -- tuios mcp. The tool list is in Agents.

Name Notes
The mcp skill topic First-party: setup, --scope all, and the tool list; also printed by tuios --skill mcp
clauth A Claude Code multi-account manager with cross-account delegation over MCP (MIT). The tuios docs list it as a herdr-plugin tool run from a command key; it is not a tuios MCP client
agent-fleet issue #54 Cites tuios’s session-scoped MCP tools as prior art; a mention, not an integration

No MCP registry lists tuios: Glama, PulseMCP, Smithery and mcp.so return only unrelated TUIO, TUUI and cmux servers.

herdr compatibility and the herdr ecosystem

tuios emulates herdr’s socket API (tracking herdr v0.9.3’s schema), exports HERDR_* variables into panes, and listens at $XDG_RUNTIME_DIR/tuios/tuios.sock.herdr. The hosted page is tuios.dev/docs/herdr-compatibility and the design note is the blog post on Crush and herdr. Which herdr methods tuios answers and refuses is in Agents.

tmux shim

tuios tmux-shim -- <command> sets TMUX, answers the tmux commands a tool issues, and opens the panes it asks for as tuios panes. The shim is documented in Sessions.

Name How it works with tuios
Claude Code agent teams tuios tmux-shim -- env CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 claude; each teammate opens as a named tuios pane with agent state
Collie, tmux mode Link tmux to the tuios binary and pass the shim socket (tmux/socket beside the daemon socket) with -S; set COLLIE_TMUX_BIN and COLLIE_MUX_ENDPOINT_TMUX
tmux-xpanes Not driven through the shim: tuios ships a native clone, tuios xpanes, modelled on it

Submitting something

If you build a dock component, a theme or an integration worth listing, the places the tuios project itself links from are the README, docs/AGENT_STATE.md for anything agent-related, and examples/dock/ for components. Open a pull request against Gaurav-Gosain/tuios following docs/CONTRIBUTING.md, or a documentation change against tuios-docs. Add it to this chapter too.
