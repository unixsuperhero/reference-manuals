Chapter 3 tuios manual

TUIOS: Keybindings and the Command Palette

Every default key in tuios v0.8.5, how modes, the leader and chords work, how to rebind or free a key, and how to drive the command palette, hints and copy mode.

tuioskeybindingsconfigpalettecli

tuios is driven from the keyboard. Every key it reacts to belongs to an action (such as new_window or prefix_split_vertical), every action lives in one of the 23 [keybindings.*] sections of config.toml, and every one of them can be rebound, unbound or handed back to the program in the pane. This chapter explains the model (modes, the leader, chords, scopes and precedence), lists every default binding section by section, shows how to change them, and then covers the surfaces that sit on top of the keymap: command keys, the command palette, hints, copy mode, the rail and the Inbox.

All tables in this chapter show the defaults of v0.8.5, with the default leader Ctrl+b. Your own config can differ. To see what your tuios does, ask the binary: tuios keybinds list, tuios keybinds doctor and tuios keybinds explain <key> (see Inspecting your bindings). The capture used while writing this chapter came from a machine whose config.toml moves the leader to Ctrl+a and the palette to Ctrl+Space, so its tuios keybinds list shows ctrl+a a for the launcher and ctrl+space for the palette. Those are overrides, not defaults.

How keys reach tuios

Two modes

tuios has two input modes, and which one you are in decides who sees a key first.

Mode Who gets an ordinary key How you enter it How you leave it
Window mode (window management) tuios. Letters such as n, x and h are commands Esc is enter_window_mode; from terminal mode, Ctrl+b Esc, or Opt+Esc (macOS) / Alt+Esc (others) i or Enter (enter_terminal_mode)
Terminal mode The program in the focused pane. Only the leader, the terminal_mode and global bindings and a few reserved chords are taken i or Enter in window mode terminal_exit_mode or the prefix chord Ctrl+b Esc

Window mode is where you arrange things: move focus with h j k l, split with - and |, close with x. Terminal mode is where you type into a shell, an editor or an agent. The dock’s mode indicator shows which mode you are in.

tuios starts in window mode. startup.start_in_terminal_mode = true starts it focused in terminal mode when a window is present (default false).

Example: open a shell, type into it, and come back

  1. In window mode press n. A new window opens.
  2. Press i (or Enter). You are in terminal mode; type ls and Enter, which go to the shell.
  3. Press Ctrl+b Esc. You are back in window mode, and x now closes the window instead of typing an x.

The leader (prefix) key

The leader, Ctrl+b by default, is the tmux-style prefix. It works in both modes. Press it, release it, then press a second key: the pair is a prefix chord, written in this manual as Ctrl+b c (a space separates the steps). The second key is looked up in [keybindings.prefix_mode].

The leader is not an entry in a table. It is the scalar keybindings.leader_key:

[keybindings]
leader_key = "ctrl+a"   # default: "ctrl+b"

Moving the leader moves every prefix chord with it: after the change above, Ctrl+a c creates a window, and the which-key panel, the help overlay and tuios keybinds list all spell chords with ctrl+a.

Rules that follow from the leader being read before everything else:

  • Leader twice sends the leader. In terminal mode, pressing the leader a second time while the prefix is armed forwards the leader itself to the pane (tmux’s prefix prefix). The pane gets it encoded as it expects: CSI u for a pane using the Kitty keyboard protocol, legacy bytes otherwise. A leader with no legacy encoding is dropped.
  • An unbound key after the leader goes to the pane. In terminal mode, a key pressed after the leader that prefix_mode does not bind is typed into the focused pane, so a stray chord never eats a letter.
  • A command key can never take the leader. An entry in [[keybindings.command]] on the leader key never runs, and tuios keybinds doctor reports it as dead.
  • tuios keybinds free cannot take the leader. It is moved, not unbound.

Example: send a literal Ctrl+B to the program in the pane

In terminal mode, with the default leader, press Ctrl+b Ctrl+b. less and vim then see one Ctrl+b and page up.

Sub-prefixes (multi-step chords)

Six keys after the leader open a further menu instead of running an action. Each sub-prefix has its own section:

Chord Opens Section Action that opens it
Ctrl+b t Window prefix [keybindings.window_prefix] prefix_window
Ctrl+b m Minimize prefix [keybindings.minimize_prefix] prefix_minimize
Ctrl+b w Workspace prefix [keybindings.workspace_prefix] prefix_workspace
Ctrl+b L Layout prefix [keybindings.layout_prefix] prefix_layout
Ctrl+b T Tape prefix [keybindings.tape_prefix] prefix_tape
Ctrl+b D Debug prefix [keybindings.debug_prefix] prefix_debug

A sub-prefix chord has three steps, for example Ctrl+b w 2 (switch to workspace 2) or Ctrl+b L s (save the layout). Esc cancels any sub-prefix.

The key that opens a sub-prefix is an ordinary prefix_mode binding (prefix_layout = ["y"] moves the layout prefix to Ctrl+b y).

Prefix repeat

After a prefix command worth pressing again, the prefix stays armed for a short window so you can repeat the second key without pressing the leader. This is tmux’s repeat-time (tmux marks such bindings -r).

The repeatable actions are the directional and stepping ones: focusing a pane in a direction, next and previous window, next and previous workspace, resizing, the scrolling layout’s column moves and width cycle, and the two agent walkers prefix_next_attention (Ctrl+b o) and prefix_next_finished (Ctrl+b O). Nothing destructive repeats, and nothing that opens a panel.

[appearance]
prefix_repeat_time = 500   # milliseconds; 0 turns repeat off; range 0 to 5000

Example: walk three panes with one leader press

Ctrl+b Left Left Left moves focus three panes to the left, as long as each arrow follows the previous one within 500 ms.

Which-key

After you press the leader, a which-key panel appears if you do not press a second key straight away (the delay is 500 ms). It lists the keys after the leader in sections: Windows, Panes, Sessions, Modes, Menus, Tools, and Agents (shown only once an agent has run in the session). A key marked with + opens a further menu (the sub-prefixes). The panel lays itself out in as many columns as the screen holds; on a screen too narrow for every column, descriptions are cut before any key is left out. Pressing a sub-prefix key shows that sub-prefix’s own panel.

Holding window mode

hold_window_mode (in [keybindings.mode_control], unbound by default) puts tuios in window mode only while a key is physically held, and hands the previous mode back on release:

[keybindings.mode_control]
hold_window_mode = ["f13"]

It needs a terminal that speaks the Kitty keyboard protocol (Ghostty, kitty, WezTerm, foot, Alacritty; not Terminal.app), because nothing else reports key release. Naming a modifier key (leftalt, rightalt, leftctrl, leftsuper) also makes every keystroke in the session arrive as an escape code; an ordinary key such as f13 to f63, scrolllock or a spare letter avoids that.

Key notation in config.toml

Every binding is a TOML array of strings. Each string is one key, optionally with modifiers joined by +.

[keybindings.layout]
split_vertical = ["|", "\\"]          # two keys, one action
swap_left      = ["H", "ctrl+left"]   # a letter and a chord

Modifiers

Write tuios reads it as Where it is valid
ctrl+, control+ ctrl+ everywhere
alt+ alt+ everywhere
opt+, option+ alt+ macOS only
shift+ shift+ everywhere
super+, cmd+, command+ super+ everywhere (needs a terminal that sends Super)
  • Order does not matter. shift+ctrl+x is ctrl+shift+x. tuios puts modifiers in one canonical order (ctrl, alt, shift, super) before comparing. This applies to leader_key, every table, and the arguments of tuios keybinds explain, free and unbind.
  • A repeated modifier is dropped, so ctrl+ctrl+x is ctrl+x.
  • super+ chords need a terminal that forwards them. Most macOS terminals keep Command for their menus; Ghostty and kitty send an unbound Command chord under the Kitty keyboard protocol.
  • On macOS, the validator suggests opt+ over a hand-written alt+ (an advisory warning, never for the shipped defaults).

A compound key is compared lowercased, so ctrl+B is ctrl+b. A key the validator cannot read (for example ctrl+ or ctrl+foo) is reported as an error naming it (unknown special key: foo), and tuios keybinds doctor lists it under key_problems.

Some chords are the same byte on most terminals: Ctrl+i is Tab, Ctrl+m is Enter, and Ctrl+[ is Esc, unless the terminal disambiguates them (the Kitty keyboard protocol does). tuios keybinds doctor reports this under OBSERVED for the terminal you run it in.

On macOS, opt+1 also matches the ¡ a composing Option key produces, so Opt digits work with no terminal setup (on a US layout).

macOS Option and Command

Option is a compose key on macOS unless the terminal is told otherwise, so an Option chord usually arrives as a character. tuios reads most composed characters back into the chord they stand for, but two kinds cannot be recovered:

  • Dead keys. Option with e, i, n, u and backtick emit nothing until a second key ends the composition. alt+n (next window in terminal mode) takes two presses on a stock macOS terminal.
  • Rewritten chords. Option+Left and Option+Right are sent as the readline word motions ESC b and ESC f; nothing says an arrow was pressed.

Command chords never reach a program inside a terminal; macOS routes them to the menu bar. The fix is the terminal’s Option-as-Alt setting:

Terminal Setting
Ghostty macos-option-as-alt = true in ~/.config/ghostty/config
Terminal.app Settings, Profiles, Keyboard, tick “Use Option as Meta Key”
iTerm2 Settings, Profiles, Keys, set Left Option key to “Esc+”
kitty macos_option_as_alt yes in ~/.config/kitty/kitty.conf
WezTerm send_composed_key_when_left_alt_is_pressed = false
Alacritty option_as_alt = "Both" under [window]
VS Code turn on terminal.integrated.macOptionIsMeta

Ghostty also needs its own arrow rewrites removed:

keybind = alt+left=unbind
keybind = alt+right=unbind

tuios says this on screen the first time it sees a chord that did not arrive as it was meant to. Without any change, the prefix still works: every navigation command has a prefix binding, and Ctrl+b is an ordinary control chord no terminal interferes with.

Other keyboard layouts

On a layout for a non-Latin script (Cyrillic, Greek, Hebrew, Arabic), a key with no binding on its typed character runs the binding of the US key at the same position: on a Ukrainian layout, Ctrl+b then the key that types ш opens the Inbox (US i). A binding on ш itself wins. Latin layouts (AZERTY, QWERTZ, Dvorak) use the letter on the key, so Dvorak’s Ctrl with the key that types b is the leader. This needs a terminal that sends the US key through the Kitty keyboard protocol (Ghostty, kitty, WezTerm, foot).

In window mode tuios asks the terminal to send every key as a code. If tuios dies without restoring it (kill -9, a dropped ssh connection), the shell shows codes such as [97u as you type. Reset the terminal with:

printf '\033[=0;1u'

Scopes, conflicts and precedence

Scopes

A scope is one keyboard context: a set of keys looked up together. Two actions on one key only collide when they share a scope. The 23 sections map onto 17 scopes:

Scope (id) Sections Entered by Effect on the pane’s program
Global (global) global always, in both modes and on the rail Takes the key from the pane
Window mode (window) window_management, workspaces, layout, mode_control, system, navigation, restore_minimized being in window mode None: tuios owns the keyboard
Terminal mode (terminal) terminal_mode being in terminal mode Takes the key from the pane
Sidebar (sidebar) sidebar the rail has focus None
Sidebar files (sidebar.files) sidebar_files rail cursor on a file row None
Sidebar agents (sidebar.agents) sidebar_agents rail cursor on an agent row None
Inbox (inbox) inbox the Inbox is open None
Inbox prompt (inbox.peek) inbox_peek a prompt is open over the Inbox None
Mailbox (mail) mail the mailbox is open None
Prefix (prefix) prefix_mode the leader Costs only the leader
Window prefix (prefix.window) window_prefix leader, t Chorded
Minimize prefix (prefix.minimize) minimize_prefix leader, m Chorded
Workspace prefix (prefix.workspace) workspace_prefix leader, w Chorded
Debug prefix (prefix.debug) debug_prefix leader, D Chorded
Tape prefix (prefix.tape) tape_prefix leader, T Chorded
Layout prefix (prefix.layout) layout_prefix leader, L Chorded
Script playback (script) script a .tape is playing None

Because the scopes are separate, the same key can mean different things in different places without a conflict: d dismisses in the Inbox list and denies in the Inbox prompt; r renames on a rail row, renames a file on a file row, and replies on an agent row; Ctrl+p is the palette globally and pauses a tape during playback.

Lookup order

In window mode, a key is tried in this order:

  1. the leader (starts a prefix chord);
  2. the window-mode scope (the seven flattened sections);
  3. the terminal_mode section (so Alt+Left focuses left in window mode too);
  4. the global section;
  5. Ctrl+c, which asks to quit.

In terminal mode:

  1. the leader (or, if the prefix is already armed, the leader goes to the pane);
  2. an armed sub-prefix or the prefix itself;
  3. the terminal_mode section;
  4. workspace and session navigation from the window-mode scope (switch_workspace_*, move_and_follow_*, next_workspace, prev_workspace, next_session, prev_session), but only for a key with a real Alt or Ctrl modifier or a macOS Option glyph, so a bare letter never stops reaching the shell;
  5. the global section;
  6. host paste (terminal_paste_host);
  7. everything else is forwarded to the pane.

Who wins a contested key

Within the window-mode scope, the seven sections are merged into one map, so a key bound in two of them is a real collision even though the TOML shows it in two tables. The rules:

  • Across sections, the later section wins. The merge order is window_management, workspaces, layout, mode_control, system, navigation, restore_minimized. A key in layout beats the same key in window_management.
  • Inside one section, the first action in alphabetical order wins.
  • The same action on the same key twice is a duplicate, not a contest.
  • Command keys never win. A [[keybindings.command]] entry on a key already taken is dead; two command entries on one key run the first one in the file.

The losing binding is shadowed: it is still in the file, but pressing the key runs the other action. The validator warns about each one on load, naming the winner and how to fix it:

[keybindings.system]
toggle_spotlight = ["x"]   # x is also close_window in window_management

system is merged after window_management, so x now toggles the spotlight and close_window keeps only w. The warning has this shape:

x runs <winner>. These never run: <losers>. Run `tuios keybinds unbind <action> x` to take the key off one of them.

Example: why the corner snaps are not on 1-4 in window mode

snap_corner_1 to _4 would be 1 to 4 in layout, and layout is merged after window_management, so they would win those keys and select_window_1 to _4 would never fire. That is why v0.8.5 ships them under the layout prefix instead: Ctrl+b L 1 to 4.

Defaults that yield to you

When tuios loads your config, an action your file does not mention gets its default back. That is how new defaults reach old configs. A handful of newer defaults yield instead: if their default key is already bound to something else in the same table, the new action is left unbound rather than stealing your key, and tuios keybinds doctor says so. The yielding actions in v0.8.5 are hints, toggle_scratch, toggle_pip, paste_image, focus_down and focus_up. Free the key and the default comes back on the next load.

For example, if your prefix_mode already binds F to another action, hints gets no key until you bind it elsewhere (hints = ["f"], after moving prefix_file_search off f).

Keys tuios takes from the pane

In terminal mode only these reach tuios rather than the program in the pane: the leader, every terminal_mode and global binding, workspace and session navigation chords, and the command keys in the global scope. tuios keybinds doctor lists them under “KEYS TUIOS TAKES FROM THE PANE”. Everything else is forwarded, including:

  • the keypad keys with Num Lock on or off (keypad Enter sends Enter), and Begin, the keypad centre key;
  • F13 and higher (a legacy-encoding program gets them in xterm’s form);
  • Insert, Delete, PgUp and PgDn with their modifiers (Ctrl+Delete stays Ctrl+Delete);
  • plain Ctrl+v, deliberately left for vim’s visual block. Host paste is Ctrl+Shift+v or Super+v.

A program on the Kitty keyboard protocol gets each key with the number the protocol gives it. Caps Lock, Num Lock and a lone modifier reach it only when it asks for every key.

The two default costs most people notice are the global Ctrl+p (fish history-back, readline previous-line) and Alt+Left/Alt+Right (word motion in readline, fish and zsh). Hand them back with tuios keybinds free alt+left or with the config shown in Unbinding. Alt+Up and Alt+Down are unclaimed by the common shells.

Rebinding

The syntax

A binding is action = [keys...] inside the section that owns the action. Writing an action replaces its default keys entirely; it does not add to them.

[keybindings]
leader_key = "ctrl+a"

[keybindings.window_management]
close_window = ["x"]            # drop the default w, keep x
new_window   = ["n", "ctrl+n"]  # two keys for one action

[keybindings.prefix_mode]
prefix_split_vertical   = ["v"]   # ctrl+a v splits left/right
prefix_split_horizontal = ["s"]   # ctrl+a s splits top/bottom
prefix_scrollback       = ["/"]   # move the scrollback browser off s

Rules:

  • The section matters. An action is looked up in the section that defines it. new_window lives in window_management; putting it in layout makes it a window-mode binding all the same (both are in the window-mode scope), but putting prefix_new_window in window_management does not make it a prefix chord. Use the action’s own section from the tables above.
  • Some actions exist in more than one section under the same name, with different meanings by scope: new_window (window mode n, rail t), launcher (global Alt+Space, prefix a), terminal_focus_left (terminal mode, and prefix Left), next_session/prev_session (window mode and prefix).
  • Multiple keys per action are listed in the array, in any order.
  • A missing line gets its default back at the next load. To change an action you must write it; to keep a default you can simply leave it out.
  • Moving a key between actions needs both lines: the new owner and the old owner without that key. Otherwise the two compete and the precedence rules decide (see Who wins a contested key).

Unbinding

An action set to an empty list has no key, and stays empty: the default does not come back.

[keybindings.terminal_mode]
terminal_focus_left  = []   # give alt+left back to readline/zsh/fish
terminal_focus_right = []   # give alt+right back too

[keybindings.global]
launcher = []               # free alt+space

An empty list and a missing line are not the same. A line your file does not have gets its default back the next time tuios loads the config; an action set to [] stays empty. The validator does not warn about an empty list, because it is the documented way to unbind.

From a shell, two commands do this for you and write the file:

tuios keybinds unbind close_window w   # take w off close_window, keep x
tuios keybinds unbind close_window     # leave close_window with no key at all
tuios keybinds free alt+left           # take alt+left off EVERY action in every scope
Command Scope of the change When to use it
tuios keybinds unbind <action> [key] One action. Name a key to remove only that one; name none to remove all of its keys “This action should not be on this key”
tuios keybinds free <key> Every action, in every scope, that holds the key “The program in my pane wants this key”

free works across every scope at once because a key that tuios still claims anywhere is a key the pane never sees. Each action that runs out of keys is written as an empty list. free cannot take the leader (move keybindings.leader_key instead) or the few keys the input path reads directly; it says so rather than reporting success.

A key tuios cannot read (bad modifier, unknown name) Error, naming the key; also key_problems in doctor
A key two actions contest Warning: which action runs, which never run, and the unbind command to fix it
new_window, close_window, enter_terminal_mode, enter_window_mode or quit with no key Warning: tuios may be difficult to use
On macOS, a hand-written alt+ Advisory warning suggesting opt+
A bad [[keybindings.command]] entry Warning; tuios ignores that entry
A [[keybindings.copy_pipe]] entry on q, Esc, v, V, /, ? or a digit Warning

config.toml is watched by every client. When you save it, the client applies what it can at once and tells you on screen if the file cannot be parsed (the running config stays in force). For keybindings the rule is:

  • Changes made through the keybind manager (record, unbind, free) take effect immediately in that client, and are written to the file.
  • Changes to [keybindings.*] tables in the file, including those written by tuios keybinds unbind and free from a shell, take effect in the next client: detach and attach again (Ctrl+b d, then tuios attach), or restart a standalone tuios.
  • For command keys, the command and the palette row change on save; a changed key works in the next client.

After any hand edit, run tuios keybinds doctor. It reads the file as tuios will and tells you about dead bindings and unreadable keys before you attach.

tuios set-config does not edit keybindings: the binding sections are tables, not scalar options, and are edited in config.toml or the keybind manager.

Command keys

A [[keybindings.command]] entry binds a key to a command you write. It is the tuios equivalent of tmux bind-key ... run-shell or display-popup, and of herdr’s custom command keybindings. Each entry also becomes a row in the command palette and in tuios keybinds list (under Commands).

Schema

Field Type Default Meaning
key string required The key. prefix+ puts it after the leader (the prefix_mode scope, e.g. prefix+alt+g is Ctrl+b Alt+g). Any other key acts in window mode and terminal mode (the global scope)
type string popup scratch, popup, pane or shell
command string required except for scratch Run with sh -c, so pipes and quotes work. Starts in the focused pane’s folder. A scratch entry without one runs your shell
description string none The name in the palette and in tuios keybinds list. Without it the label is Run <command>
name string derived A stable name for the entry (and its scratch terminal). Default: a slug of the description, else of the command, else of the key
width, height string 80% Size of a scratch or popup box, in cells (100) or percent (80%)
type What happens
scratch A scratch terminal of its own, toggled by the key like Ctrl+b g. It has its own layout (you can split it). One scratch is on screen at a time. When the command exits its pane closes; with no pane left, the next press starts it again
popup A popup that closes when the command exits
pane A new pane in the layout next to the focused one; closes when the command exits
shell Runs with no window. You do not see output; a failure shows in the dock

The command’s environment:

Variable Value
TUIOS_SESSION The session in which you pressed the key
TUIOS_SOCKET The daemon’s socket
TUIOS_ACTIVE_PANE_ID The pane that had focus
TUIOS_ACTIVE_PANE_CWD The folder the command starts in

Each entry is the action command:<name>, which is how tuios keybinds doctor and the keybind manager refer to it.

Rules and edge cases

  • A command key never takes a key from a tuios action or from the leader. If the key is taken, the entry is dead (doctor shows it). Two entries on one key: the first in the file runs.
  • A bare key without prefix+ or a modifier (for example g) is in the global scope and so takes that letter from every pane. tuios warns. Use prefix+g or alt+g.
  • Invalid entries are warnings, and tuios ignores the entry: no key, an unknown type, no command on a non-scratch entry, an unusable name, the reserved name scratch (the built-in scratch terminal), an unreadable key, or a bad width or height. A second entry with the same name is ignored.
  • Reload. Saving the file updates an entry’s command and palette row. A changed key works in the next client. Removing or renaming an entry (or changing the description of an entry that has no name) closes its scratch panes at the next reload, with a dock message.
  • Failure on start. A scratch command that stops in its first moments (not installed, for instance) shows its exit code in the dock. tuios does not restart it by itself.
  • Remote sessions. In a session on another machine, scratch and popup entries do not run (the dock says so). A pane entry runs on the session’s machine; a shell entry runs on the machine that runs the tuios client.
  • Who can run one. Only a key press or the palette. Changing config.toml never runs a command. A pane with the respond grant can press keys as you through run-command, including a command key, so give that grant only to panes you trust.

Examples

Example 1: lazygit in a scratch box, in the focused pane’s folder

[[keybindings.command]]
key = "prefix+alt+g"
type = "scratch"
command = "lazygit"
description = "Lazygit"
width = "80%"
height = "80%"

Ctrl+b Alt+g shows the box, pressing it again hides it, and lazygit keeps running in between. The palette has a “Lazygit” row in the Commands category with the shortcut prefix+alt+g.

Example 2: pick a file with fzf and type it into the pane you came from

[[keybindings.command]]
key = "prefix+alt+p"
type = "popup"
command = "tuios send-text -w \"$TUIOS_ACTIVE_PANE_ID\" \"$(fzf)\""
description = "Pick a file"

The popup closes when fzf exits, and tuios send-text types the pick into the pane named by TUIOS_ACTIVE_PANE_ID (see CLI).

Example 3: copy the pane’s folder to the clipboard, no window

[[keybindings.command]]
key = "prefix+alt+y"
type = "shell"
command = "printf %s \"$TUIOS_ACTIVE_PANE_CWD\" | (pbcopy || wl-copy || xclip -selection clipboard)"
description = "Copy pane folder"

Nothing opens. If none of the three clipboard tools exists, the dock shows the failure.

Run tuios keybinds doctor after adding any entry to check that its key is free.

Once you type, the headers go. Rows are ranked by how well their name matches (a fuzzy, scored match; the matched letters are lit), and each row names its category in a quiet column on the right. A row admitted only because its category matches comes after every name match, so typing layout lists the Layout section below anything actually called layout. Settings rows come last of all.

The right-hand slot of a row is its key or its consequence: prefix+c for New window, another machine for a session on another host, unread for a mail thread. For the built-in command rows this label is fixed text for the default layout; for command-key rows and # rows it is read from your config.

Example: three ways to split

Open the palette and type spl. “Split horizontal”, “Split vertical” and “Smart split” rank first, with spl underlined. Down, Enter runs the split.

State filters: the @ token

A query that starts with @ narrows the list to panes in an agent state. Only the session and window rows carry a state, so every static command drops out. The state name is matched by prefix, so one letter is enough:

Token Admits panes whose agent is
@a, @attention needing input or errored (the same definition as the rail’s attention mark)
@w, @working working
@n, @needs_input waiting for input
@d, @done done
@i, @idle idle
@e, @errored errored
@ alone any pane running an agent

A token naming no state (a typo) admits nothing, so you see an empty list rather than a filter that silently did not apply. Text after the token is matched as usual: @a server ranks the attention panes whose names match server.

Example: jump to whichever agent needs you

Ctrl+p, type @a, Enter. The palette switches session if it must and focuses that pane. The rail’s / opens the same palette, ready for the same token.

Keybinding rows: the # token

A query that starts with # turns the palette into a search over actions. Every action gets one row, whatever it is bound to, built from the registry:

  • the row’s name is the action’s description followed by the action name, for example Close current window prefix_close_window, so you can search by either the words or the config name;
  • the right-hand slot lists every key that reaches the action, chord included (ctrl+b x), or unbound;
  • Enter opens the keybind manager filtered to that action, where each of its bindings can be rebound or unbound.

# is exclusive both ways: a # query lists only action rows, and no other query ever lists them, so a few hundred actions never bury the commands. A bare # lists every action, which is also the answer to “what can I rebind?”. The “Rebind a key” and “Unbind a key” rows advertise this with or type #close in their key slot.

Two of the rows #zoom finds, with a default config:

Row name Key slot
Toggle zoom (fullscreen) toggle_zoom z
Fullscreen current window prefix_fullscreen ctrl+b z

Settings rows

Every settings row is also a palette row, matched as Settings: <name>, with its tab in the key slot. Type the setting’s name (pane background) or the prefix (settings: pane background); Enter opens the settings page on that row.

Agent entries

The Agents category holds the agent commands (named “Agents: …” so typing agent lists them): the mailbox, the Inbox, the Inbox on its mail, the oldest waiting item, and the review of the focused pane. Session and window rows for panes running an agent carry a coloured state glyph, which is also what the @ filter reads. Unread mail threads appear as Mail #N ... rows; selecting one opens the mailbox on that thread. See Agents.

Hints mode

Hints mode puts a short label on each useful piece of text in the focused pane (URLs, paths, hashes, addresses, numbers and more) so you can copy it by typing the label. It works like tmux-fingers or kitty’s hints kitten.

Key What it does
Ctrl+b F Start hints (hints in prefix_mode)
a label, such as a or ls Copy the text and close
the label with Shift, such as A Copy the text and type it into the pane
the label with Ctrl, such as Ctrl+a Open a URL in the browser or a path in $EDITOR in a new pane
Backspace Remove the last label letter typed
Esc, or the leader Close
q Close, when q is not a label letter
Ctrl+c, Ctrl+g Close, when c / g is not a label letter (with the default alphabet, g is a letter, so Ctrl+g opens label g)

The nearest text to the cursor gets the shortest label, and the same text gets the same label every time. While labels show, hints mode keeps all input from the pane. A click or the wheel closes it first; so does the pane closing, the focus moving, or a workspace change. The palette has it too (search hints).

All panes

hints_all_panes labels every pane the workspace shows (tiled, floating, focused), giving the focused pane the shortest labels and the nearest panes the next shortest. Labels are unique across panes; Shift and a label types the text into the focused pane even if it came from another; Ctrl and a label opens it using the folder and machine of the pane that shows it. Text you cannot see (minimized, behind a zoomed pane, off screen, under another pane) gets no label.

The action has no default key. Bind it, or make Ctrl+b F do it:

[keybindings.prefix_mode]
hints_all_panes = ["A"]

[hints]
all_panes = true   # default false: Ctrl+B F labels only the focused pane

Hints settings

Option Default Meaning
hints.builtins "all" "all", "none", or names such as "url,path,sha"
hints.patterns [] Extra Go regular expressions, tried before the built-ins; a group named match sets what is copied
hints.alphabet "asdfghjkl" Label letters, easiest first, lowercase
hints.open true Let Ctrl and a label open the text
hints.dim 60 How much the rest of the pane dims, 10 to 90 percent
hints.all_panes false Ctrl+b F labels all panes

The built-in patterns are url, path, diff, sha, ip, uuid, color, hex, number (4 digits or more), email and id (Kubernetes-style resource names and sha256: digests). All but hints.patterns are on the settings page (Selection tab) and work with tuios set-config. Full details, including when Ctrl copies instead of opening, are in the upstream HINTS.md.

Copy mode, search and selection

Entering and leaving

Ctrl+b [ (prefix_selection) starts copy mode on the focused pane. The copy cursor starts on the terminal cursor, usually the prompt line, as in tmux. Set appearance.selection.copy_entry = "center" to start on the middle row instead.

Key What it does
q, Esc Leave copy mode
i Leave copy mode and enter terminal mode

Copy mode’s keys are its own vim-style grammar, not bindings in a [keybindings.*] section, so they cannot be rebound (only extended with [[keybindings.copy_pipe]], below). Inside copy mode, the leader does not start a chord, because copy mode uses Ctrl+b for page up. tuios send-keys and tapes cannot drive copy mode: it ignores remote keys.

Motion

A number typed first repeats a motion (5j), and a number before G goes to that line (10G).

W / B / E The same by WORD (whitespace-separated)

gg / G Top of the scrollback / bottom
H / M / L Top / middle / bottom of the screen

Ctrl+b, PgUp / Ctrl+f, PgDn A page up / down
{ / } Previous / next paragraph

Search

Key What it does
/ Search forward, down toward the newest output
? Search backward, up into the scrollback
n Next match in the direction of the last search
N Next match in the opposite direction

The prompt shows / or ? for the direction. A search starts at the copy cursor and wraps to the other end of the buffer when nothing is found in that direction. More than 1000 matches shows 1000+.

Two actions enter copy mode and open the search prompt in one key, like tmux bind-key b copy-mode \; send-keys ?. They have no default key:

[keybindings.prefix_mode]
copy_mode_search_backward = ["/"]   # ctrl+b / searches up into the scrollback
copy_mode_search_forward  = ["alt+/"]

The palette has them as “Copy mode: search forward” and “Copy mode: search backward”. If the pane is already in copy mode, the action just opens the prompt without moving the cursor. Bound in global, terminal_mode or window_management, the key also works from inside copy mode; bound under the leader, it works only from outside (copy mode keeps Ctrl+b).

Selecting and yanking

Key What it does

Lists, panels and settings

Every list in the TUI (the palette, launcher, settings, Inbox, mailbox, keybind manager, every picker and menu, the dock and rail editors, the tape manager) moves the same way: Up/Down or Ctrl+p/Ctrl+n one row (wrapping unless appearance.wrap_lists = false), Home/End the ends, PgUp/PgDn a page, j/k/g/G in a list with no filter, Ctrl+u to clear a filter, and the wheel. The close-session and file confirmations never wrap, so up from Cancel cannot land on the destructive answer.

The settings page (, in window mode, Ctrl+b ,) uses the same list keys, plus Left/Right to change a value, Tab for tabs, / to search and Backspace to reset a row. The help overlay (? in window mode, Ctrl+b ?) lists the bindings read from your config, including an Agents section and the mouse gestures.

Glossary

Chord
A key with modifiers (ctrl+shift+v), or in this manual also a sequence of presses after the leader (Ctrl+b w 1).
Command key
A [[keybindings.command]] entry: a key that runs a command you write, as a scratch, popup, pane or windowless shell command.
Dead binding
A binding that never runs because another action, earlier or later by the precedence rules, holds its key. Also shadowed.
Leader
The prefix key, keybindings.leader_key, Ctrl+b by default.
Prefix repeat
The window after a repeatable prefix command during which the second key can be pressed again without the leader (appearance.prefix_repeat_time).
Scope
One keyboard context whose keys are looked up together. Conflicts exist only inside a scope.
Sub-prefix
A menu opened by a key after the leader (t, m, w, L, T, D) with a section of its own.
Yielding default
A newer default that stays unbound when your config already uses its key.
